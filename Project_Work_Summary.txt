1. PROJECT OVERVIEW
================================================================================

This project implements an end-to-end Machine Learning pipeline for detecting
and diagnosing operational faults in Autonomous UAV (Unmanned Aerial Vehicle)
systems using onboard telemetry sensor data. The system classifies flight
telemetry into four operational states:

  1. Normal Flight (Nominal cruise and hover dynamics)
  2. Propeller Imbalance (Blade mass defect / aerodynamic asymmetry)
  3. Battery Degradation (Internal cell resistance rise / voltage collapse)
  4. Motor Failure (Stator overload / thermal spike / electrical stall)

The pipeline ingests raw sensor data (MATLAB .mat, CSV, HDF5, Parquet), cleans
and standardizes telemetry channels, extracts rolling time-series and FFT
vibration harmonics, trains a regularized LightGBM classifier with safety-critical
asymmetric decision boundaries, and serves predictions through an interactive,
high-aesthetic Streamlit Ground Control Station (GCS) dashboard featuring
Explainable AI (XAI) root-cause diagnostic reasoning and fault contrast.

3. WHAT WAS BUILT — MODULE BY MODULE
================================================================================

------------------------------------------------------------------------
MODULE 1: Data Ingestion & MATLAB Synchronization (src/ingestion.py)
Lead: Manideepa Mohapatra & Prasun Kumar Biswas
------------------------------------------------------------------------
- Native MATLAB .mat Synchronization Engine:
  Re-engineered MATLAB's sync_zoh_exa.m / sync_resample_exa.m into Python.
  Synchronizes multi-rate ArduPilot DataFlash telemetry (IMU at 400Hz, VIBE at
  100Hz, ESC at 10Hz) into a uniform 50 Hz time-grid using Zero-Order Hold (ZOH)
  and linear interpolation along TimeUS timestamps.
- Native DronePropB Test Bench Ingestion:
  Automatically detects 1,000 Hz – 10,000 Hz acoustic and IMU accelerometer
  structures (IMUData, BatteryVolt) and downsamples cleanly to 50 Hz RMS vibration.
- Recursive directory scanner supporting .csv, .parquet, .mat, .h5/.hdf5,
  and .json telemetry files.
- Heuristic fault labeling inferred from file and directory naming conventions
  (e.g., "FAULT_M" -> Motor Failure, "NO_FAULT" -> Normal Flight, "F1/F2/F3" -> Propeller).
- Automated Flight_ID assignment extracted directly from source filenames.

------------------------------------------------------------------------
MODULE 2: Data Cleaning (src/cleaning.py)
Lead: Omm Shree Hota & Manideepa Mohapatra
------------------------------------------------------------------------
- Fuzzy column alias resolution mapping 40+ raw sensor column aliases into 4
  canonical engineering channels: Battery_Voltage, Current, Temperature, Vibration.
- Per-flight Winsorization (IQR and Z-score outlier clipping applied via
  groupby("Flight_ID")). Global clipping was identified as masking critical
  fault signatures (such as Motor Failure's 28A surge) and was replaced with
  per-flight grouping.
- Time-series linear interpolation with forward and backward fill, isolated
  per flight to strictly prevent inter-flight data leakage.
- Explicit KeyError validation raised when essential telemetry channels are missing.

------------------------------------------------------------------------
MODULE 3: Feature Engineering (src/feature_engineering.py)
Lead: Milan Mandal & Prasun Kumar Biswas
------------------------------------------------------------------------
- 14 engineered features extracted across rolling time-series and frequency domains:
    Raw Channels:    Battery_Voltage, Current, Temperature, Vibration
    Rolling Domain:  Voltage_Roll_Mean, Vibration_Roll_Var, Vibration_Roll_RMS,
                     Current_Roll_Mean, Temperature_Roll_Mean
    Derived Domain:  Electrical_Power (V * I)
    Spectral Domain: Vibration_FFT_Peak_Freq, Vibration_FFT_Peak_Power,
                     Vibration_Spectral_Centroid, Vibration_Harmonic_Energy_Ratio

- Vectorized Sliding-Window FFT:
  Implemented using np.lib.stride_tricks.sliding_window_view and batched
  np.fft.rfft, replacing an O(n * window_size) nested Python loop and reducing
  computation time from minutes to milliseconds.

- Baseline Calibration Anchor:
  StandardScaler is fitted strictly on verified "Normal Flight" baseline data
  (mean=0, std=1 for nominal state), ensuring fault deviations are measured
  relative to healthy flight physics.

- Explicit Canonical Target Encoding:
  Implemented `ExplicitLabelEncoder` with fixed canonical mapping:
    0: Normal Flight
    1: Propeller Imbalance
    2: Battery Degradation
    3: Motor Failure
  Guarantees consistent index mapping across training, evaluation, and dashboard,
  eliminating scikit-learn's default alphabetical sorting bug.

------------------------------------------------------------------------
MODULE 4: Model Training (src/model_training.py)
Lead: Prasun Kumar Biswas & Ipsita Priyadarshini
------------------------------------------------------------------------
- Multi-algorithm training and comparative evaluation: Random Forest vs. LightGBM.
- StratifiedGroupKFold cross-validation grouped by Flight_ID to evaluate
  generalizability across unseen flights.
- Production-grade LightGBM regularization:
    n_estimators=300, learning_rate=0.05, max_depth=8, reg_alpha=0.1,
    reg_lambda=1.0, min_child_samples=20, subsample=0.8, colsample_bytree=0.8,
    class_weight="balanced"
- Early stopping (20 rounds) with validation callback during cross-validation.
- Class-filtered eval_set: prevents scikit-learn LabelEncoder exceptions when
  validation folds have disjoint class distributions.
- Feature importance calculation (split count) exported to feature_importance.json.
- Full pipeline model serialization using joblib.

------------------------------------------------------------------------
MODULE 5: Evaluation & Cost Matrix (src/evaluation.py)
Lead: Ipsita Priyadarshini & Prasun Kumar Biswas
------------------------------------------------------------------------
- Safety-critical asymmetric decision boundaries favoring high recall for
  catastrophic failures:
    Motor Failure:        >= 0.25 (highest priority, overrides all)
    Propeller Imbalance:  >= 0.30
    Battery Degradation:  >= 0.30
    Normal Flight:        argmax fallback
- Vectorized threshold decision logic using NumPy boolean masking.
- 4x4 operational cost matrix penalizing missed high-severity failures:
    Missed Motor Failure        = 500 penalty units
    Missed Propeller Imbalance  = 50 penalty units
    Missed Battery Degradation  = 50 penalty units
    False alarms on Normal      = 5 penalty units
- Comprehensive metrics output: per-class Precision, Recall, F1, Support,
  Macro-F1, Confusion Matrix, and aggregate Operational Cost Penalty.
- JSON report export to models/evaluation_report.json with ISO timestamp.

------------------------------------------------------------------------
MODULE 6: Ground Control Station Dashboard (app.py)
Lead: Sneha Singh & Prasun Kumar Biswas
------------------------------------------------------------------------
- High-aesthetic Streamlit GCS user interface with dark glassmorphism HUD.
- Dual Operational Downlink Modes:
    (a) Simulated Real-Time Replay: Streams telemetry sample-by-sample with
        live gauges, animated Plotly charts (voltage, current, vibration),
        and active multi-class probability gauges.
    (b) Offline Flight Log Analysis: Batch processes uploaded flight logs,
        applies asymmetric thresholding, plots flight trajectory states,
        and provides aggregate state distributions.
- Dedicated Start/Stop Controls: Session-state managed "▶️ Start Live Telemetry
  Downlink" and "⏹️ Stop Downlink" buttons for non-blocking mission control.
- Configurable Playback & Sensitivity: Slider controls for playback speed (0.5x
  to 5.0x) and Motor Fail alarm threshold (0.10 to 0.50).
- Explainable AI (XAI) Diagnostic Reasoning & State Discrimination Card:
    - Root-Cause Evidence: Explains the exact physical and sensor mechanism
      driving the diagnosed state using live telemetry values (e.g. current surge,
      thermal climb, voltage collapse, vibration resonance).
    - Contrastive State Elimination: Explicitly states why each of the other
      three operational states was ruled out, providing complete transparency
      to the flight operator.
- Model Diagnostics Sidebar Expander:
    - Displays held-out Test Macro-F1 score and Operational Cost Penalty.
    - Interactive horizontal bar chart of top-8 LightGBM feature importances.
- Self-Explanatory Flight Log Selection: Dropdown lists descriptive flight files
  indicating flight type and condition.

------------------------------------------------------------------------
MODULE 7: Pipeline Orchestrator (main.py)
Lead: Prasun Kumar Biswas
------------------------------------------------------------------------
- Coordinates all pipeline stages: Ingestion -> Cleaning -> Feature Engineering
  -> Grouped CV -> Model Training -> Asymmetric Evaluation -> Artifact Export.
- Deterministic synthetic benchmark generator creating 5 realistic flight missions
  (2 healthy flights, 1 propeller fault, 1 battery fault, 1 motor fault).
- GroupShuffleSplit flight-level train/test partitioning.
- Dual-phase training: validates model on training flight groups, then trains
  production model on all data for deployment.
- Exports 5 production artifacts to models/:
    uav_fault_model.joblib, feature_engineer.joblib, cleaner.joblib,
    evaluation_report.json, feature_importance.json
